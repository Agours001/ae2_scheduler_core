# 调度核心

<Row>
  <ItemImage id="scheduler_core" scale="4" />

  <BlockImage id="scheduler_core_block" scale="4" />
</Row>

**让一台合成 CPU 同时接纳多个合成订单。**

原版一台合成 CPU 一次只能处理一个订单。想同时合成两种东西，就得造第二台 CPU。
装上调度核心之后，一台 CPU 可以同时接下多个订单，按**时间片**在它们之间轮转——
而且轮到谁，谁的表现就和原版单任务 CPU 完全一样。

---

## 本模组解决了什么问题

原版的限制不在于 CPU 算不过来，而在于**它只能受理一个请求**：

* 你想同时合成 1000 根木棍和 500 个处理器，必须造两台 CPU。
* 第二台 CPU 意味着第二套合成存储、第二组并行单元——**资源翻倍，只为多接一个订单**。
* 只有一个订单时，多出来的 CPU 完全闲置。

调度核心把"排队"变成"轮转"：

| | 原版 | 装了调度核心 |
|---|---|---|
| 一台 CPU 能接几个订单 | 1 个 | **多个** |
| 同一时刻有几个订单在跑 | 1 个 | **仍然只有 1 个** |
| 单个订单执行时的速度 | 原版速度 | **与原版完全一致** |
| 总产能 | 基准 | **不放大、不缩水** |
| 接多个订单的代价 | 再造一台 CPU | **给现有 CPU 装一个调度核心** |

关键点：**它不会让 CPU 变快**。它只是让你不必再造第二台 CPU 来排队。
所以它也不会破坏平衡——同一台机器上，N 个订单各自耗时约为原来的 N 倍，总量不变。

---

## 调度核心部件

<ItemImage id="scheduler_core" scale="4" />

**调度核心部件**是这个模组的核心材料，本身不是方块。它有两种用法：

1. **与合成单元合成**，直接得到调度核心方块；
2. **对着世界里已有的合成单元方块使用**（手里拿着部件右键），把它就地改造成调度核心方块。
   这用的是 AE2 自己的"合成单元改造"机制，和 AE2 把合成单元升级成合成存储是同一套操作。

<RecipeFor id="schedulercore:scheduler_core" />

> **每个合成 CPU 最多安装一个调度核心。** 装第二个不会生效：AE2 会拒绝让这个多方块成型。
> 放下第二个时你会收到一条提示。

---

## 调度核心方块

<BlockImage id="scheduler_core_block" scale="4" />

**调度核心方块**是装进 CPU 多方块的那一块。它本身：

* **不提供合成存储**（0 字节）——CPU 的容量仍然完全由你的合成存储方块决定；
* **不提供并行单元**（0 线程）——CPU 的速度仍然完全由你的并行单元决定。

也就是说，**装一个调度核心不会改变这台 CPU 的容量或速度**，只是让它能接多个订单。

它和普通合成单元一样是 CPU 多方块的一个组成部分，成型后会跟着 CPU 一起亮起来、一起连接到网络。

<RecipeFor id="schedulercore:scheduler_core_block" />

也可以**手里拿着部件，对着世界里已有的合成单元方块右键**，把它就地改造，不需要工作台。
这走的是 AE2 自己的"合成单元改造"配方类型，和把合成单元升级成合成存储是同一套操作。
（这种配方没有物品输出，指南和 JEI 都只能示意，故此处不列出图示。）

---

## 如何加入 CPU 多方块

调度核心方块**就是一块合成单元**，所以做法和摆普通合成单元完全一样：

1. 搭一个**实心长方体**的 CPU 多方块（不能有空洞、不能缺角）；
2. 把**调度核心方块**放在这个长方体里的**任意位置**；
3. 长方体里**至少要有 1 块合成存储**（这是原版规则，调度核心不能替代存储）。

**最简单的可用做法**：把现有 CPU 里的一块普通合成单元换成调度核心方块。
不需要拆掉整台 CPU，也不需要增加方块数量。

### 需要注意的地方

* **一个 CPU 只能有一个调度核心。** 放了两个，这个多方块会**拒绝成型**。
  此时用 `/schedulercore rig status` 之类的诊断命令看不出来，直接看 CPU 是否成型即可。
* **调度核心不替代存储。** 只有调度核心和普通合成单元的 CPU 是**不成型**的，
  原版就要求至少一块合成存储。
* **拆除含调度核心的 CPU 时，任何方块都可能触发 AE2 自身的一个异常**
  （`The node has already been initialized`），导致那一次拆除中断。
  你的订单和材料不会丢：拆除流程会先取消全部订单并把材料退回网络，异常发生在之后。
  重新放置方块即可，这是 AE2 自身在 teardown 阶段的行为，本模组无法修正。
* **取走调度核心会取消这台 CPU 上的全部订单**，材料退回网络（这是原版拆任何 CPU 方块的行为）。
* 装上核心后，CPU 的受理逻辑就由调度核心接管。**没装核心的 CPU 完全不受影响**，走原版逻辑。

## 装好之后

* **可以连续提交多个订单**：CPU 忙碌时也能继续下单，只要它的合成存储放得下新订单用的中间材料。
* **合成状态界面里每个订单一行**：每一行有自己的名称、进度和预计时间，点一行可以查看详情。
* **可以逐单取消、逐单挂起/恢复**：只影响你选中的那个订单。
* **回料会回到正确的订单**上，即使多个订单同时在跑也不会记错。
* **存档会逐个订单保存**，重启服务器/重进游戏后队列还在。

### 一个必须知道的限制

**取消订单时，该订单"已抽进 CPU 的原料"只有在没有其他订单会用到它们时才会立即退回网络。**

原因是 AE2 的 CPU 库存是所有订单共用的一个池子，而 AE2 不记录"哪些材料属于哪个订单"。
所以：

* 被取消订单的原料，如果其他订单**不需要** → **立即退回网络**；
* 与其他订单**共用**的原料 → **留在 CPU 里**，直到这台 CPU 上所有订单都结束才一起退回。

材料不会丢失，只是归还的时机和你预期的可能不同。

### 另外几个已知情况

* 合成状态界面的物品表是**整台 CPU** 的视图：显示的是共享库存的数量，不是某个订单的份额。
* 正常做完并留下材料的订单，和原版一样，等 CPU 空闲时才清理。
